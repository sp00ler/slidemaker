# Проверка качества генерации

После начальной генерации и необязательного дополнения слайдов редактор проверяет содержание и структуру колоды. При замечаниях выполняется не более одной попытки исправления, затем редактор проверяет результат ещё раз. Дополнительные вызовы модели увеличивают стоимость и задержку, но число попыток ограничено. Если проблемы остаются, заказ получает ошибку вместо готового файла.

Что проверяется:
- заданное число слайдов, титул и заключение;
- пустые пункты, технические заглушки и дублирование слайдов;
- смешение русского и английского в подписях визуалов;
- противоречие между годом основания и заявленным числом лет истории;
- наличие источника и чисел графика в предоставленных материалах;
- смысловая связность слайдов, полнота раскрытия темы и соответствие исходным материалам;
- видимые ссылки на источники только для сведений, подтверждённых материалами заказа;
- получение каждого запланированного визуала перед выдачей заказа.

Редактор не проводит независимый поиск фактов. Ссылки на слайдах должны вести только к источникам из материалов заказа; отсутствие подходящего источника не разрешает придумывать ссылку. Ни автоматическая проверка, ни повторная редактура не гарантируют абсолютную фактическую точность: совпадение чисел с исходным материалом не доказывает корректность их интерпретации, а незамеченные ошибки остаются возможны.

## Изменённые файлы

- `lib/anthropic.ts`: доступность визуальных сервисов, инструкции по композиции, одна попытка исправления.
- `lib/deck-quality.ts`: проверка содержания.
- `lib/visuals.ts`: сохранение происхождения фотографии, схемы и сгенерированной иллюстрации.
- `lib/generate.ts`: запрет выдачи при потере визуалов и повторной полной генерации после ошибки качества.
- `lib/pptx.ts`: композиции по содержанию, сохранение фото и схем, автоматическая палитра, компактные сравнения, удаление рекламного подвала.
- `lib/__tests__/anthropic.test.ts`, `order-wishes-storyboard.test.ts`, `pptx.test.ts`, `visuals.test.ts`: регрессии.
- `package.json`: включение тестов визуалов.
- `scripts/preview-quality.mjs`: локальные примеры вёрстки.
- `scripts/smoke-generation-quality.mjs`: отдельная проверка настоящей генерации через API без заказа и писем.

## Локальные примеры

```powershell
node scripts/preview-quality.mjs
```

Создаёт `tmp/quality-preview/quality-preview-academic.pptx` и `quality-preview-business.pptx`. Это тестовые слайды: даты и содержание помечены как примеры. Использованные локальные PNG проверяют размещение, а не качество подбора фотографий. Скрипт не обращается к API.

## Проверки

```powershell
npm test
npm run build
```

Проверка настоящей генерации с расходом API:

```powershell
node scripts/smoke-generation-quality.mjs
```

Она использует локальную конфигурацию API, ограничена 180 секундами и сохраняет результаты в `tmp/quality-live/`. Данные примера не являются независимо проверенным исследованием.

## Текущий промежуточный статус

На 2026-10-01: локальная проверка — 90 тестов, build и `git diff --check` прошли. Два младших агента gpt-6-luna исправили инструкции против неподтверждённого заполнения, уточнили отношение к summary и порядок операций в Mermaid; smoke-скрипт обновлён синтетическим fixture с достаточными материалами и отключением photo/gen-art до генерации.

В `lib/visuals.ts` Kroki остаётся primary renderer; при сетевой ошибке, non-OK ответе или ошибке чтения тела выполняется один fallback-запрос к Mermaid Ink. Вторичный renderer получает тот же Mermaid source (`code`, включая init/theme) по HTTPS в сжатом Base64URL JSON payload. Timeout — 20 секунд на каждый последовательный запрос, максимум 40 секунд на diagram; retries нет. Ответы пока принимаются по HTTP status без проверки PNG signature.

Начальная генерация и semantic check ранее прошли. Затем отдельный `resume-render` вне sandbox обработал сохранённый deck: 8 слайдов, разрешены все 5 из 5 diagram visuals, сохранён свежий `tmp/quality-live/deck.pptx`. Независимый visual QA всех 8 PNG завершён: обрезаний и перекрытий нет, схемы читаемы, порядок на слайде 5 верный; blocking defects не обнаружены. У слайда 2 заголовок тесноват, подписи на слайдах 2 и 7 расположены близко к низу. При осмотре слайда 2 в 1920×1080 подпись оставляет около 180 px до нижнего края, заголовок читаем и обычный интервал сохранён; подтверждённого дефекта нет. Это split-stage integration validation сохранённого deck, не fresh one-shot smoke и не production deployment.

Fixture и deck синтетические, учебные данные и утверждения не являются проверенными сведениями о реальной организации. Результат относится к этой колоде и не гарантирует универсальное качество генерации; разрешение внешних visuals зависит от доступности сетевых renderer-сервисов.

## Что проверить вручную в сервисе

1. Английская тема об университете: подписи тоже на английском, нет выдуманного рейтинга без исходных чисел.
2. Академический пресет с загруженной фотографией или схемой: визуал присутствует, пропорции сохранены.
3. Хронология с датами 1365 и 2004: содержимое оформляется как последовательность событий.
4. Русская тема с длинным заголовком: текст не пересекается с содержимым или визуалом.
5. Автоматическое оформление: палитра модели применяется; выбранные пользователем цвета имеют приоритет.
6. Недоступный сервис схем или фотографий: заказ не получает статус готового с потерянными визуалами.

Строгая проверка визуалов повышает число ошибок заказов при сбоях внешних сервисов. Фотографии из поиска требуют `PEXELS_API_KEY`; без него модель получает инструкцию не планировать такие фотографии. Загруженные изображения доступны независимо от этого ключа.
