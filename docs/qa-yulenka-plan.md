### Волна 2 (v2, утверждена владельцем 02.07) — «Требования к оформлению» + ВКР-каркас

Замечания 7, 8, 9 + идея владельца: университеты диктуют требования к оформлению; сервис должен принимать их, а не заставлять редактировать вручную. Референсы: `docs/pravilaPrezentacii.pdf` (правила СФУ — база default-пресета), `docs/ex1.png`, `docs/ex2.png` (эталон академического стиля: белый фон, тонкие рамки-боксы, нумерация с вертикальными штрихами, ALL-CAPS заголовки, двухколоночная сетка).

**Модель данных — `orders.prefs` JSONB (nullable), миграция `006_order_prefs.sql`:**

```json
{
  "preset": "academic" | "auto" | "custom",
  "workType": "vkr" | "coursework" | "report" | "generic",
  "title": { "mode": "auto" | "self" | "upload", "fileId": "<uuid?>" },
  "fonts": {
    "heading": { "face": "Arial", "size": 32, "bold": true, "italic": false },
    "body": { "face": "Arial", "size": 24 }
  },
  "palette": { "bg": "FFFFFF", "text": "1A1A1A", "accent": "1F3A5F" }
}
```

- `preset: "auto"` = текущее поведение (ИИ подбирает всё) — prefs может быть null.
- `preset: "academic"` = default для новых заказов. Фиксированный DesignSpec: bg `FFFFFF`, ink `#1A1A1A`, один сдержанный accent (тёмно-синий `1F3A5F`) только на номера/штрихи/подчёркивания; стандартные шрифты (Arial default; select: Times New Roman, Arial, Tahoma, Verdana, Calibri); минимум декора; ALL-CAPS только в заголовках слайдов.
- `preset: "custom"` = юзер крутит шрифты/размеры/палитру сам (свёрнутая секция).
- Шрифты — только whitelist стандартных (есть на любой машине, pptx не тащит embed).

### Волна 2.1 (фидбек владельца 03.07 по живой форме)

**T4e. Sonnet 5 — человеческий UX кастом-настроек (`app/page.tsx`, при необходимости `app/globals.css`)**

Жалобы владельца: непонятно, что настраиваем и зачем; hex-коды понимают «только роботы»; плитки Office-тем не объясняют, что произойдёт при клике; нет выбора подложки (фон всегда белый); нет подписей и подсказок.

- Каждое поле: человеческий label + короткий серый hint-текст под полем (не только `title`-тултип — на мобилке hover нет; `title` добавить дополнительно).
  - «Шрифт заголовков» — hint: «названия слайдов и крупные надписи»;
  - «Шрифт основного текста» — hint: «пункты списков и подписи»;
  - «Размер заголовка (pt)» / «Размер текста (pt)» — hint: «как в PowerPoint; для аудитории обычно ≥24 pt»;
- Цвета — БЕЗ голых hex-инпутов. Каждый цвет = нативный `<input type="color">` (кружок-пикер) + синхронное hex-поле рядом для тех, кому нужно точное значение. Подписи:
  - «Фон слайда (подложка)»;
  - «Цвет текста»;
  - «Акцентный цвет» — hint: «линии, номера, подчёркивания».
- Подложка: ряд из 4–5 свотчей-пресетов фона над пикером (Классический белый FFFFFF, Слоновая кость F7F5EF, Светло-серый F2F4F7, Тёплая бумага FAF7F0…). Клик — подставляется в «Фон слайда». Выбранный подсвечен.
- Плитки Office-тем: на каждой плитке 3 цветовых кружка-свотча (фон/текст/акцент) вместо hex-кода, label остаётся; hint над блоком: «Готовые сочетания — нажмите, и цвета подставятся в поля выше»; выбранная тема подсвечивается как active.
- Live-превью (DesignPreview) продолжает мгновенно отражать всё.
- Stop: build+typecheck+test зелёные, без коммита.

**T7. Codex — промокоды со скидкой (backend, `app/page.tsx` НЕ трогать — конфликт с T4e)**

Владелец: нужен быстрый механизм — сам выбираю скидку, генерирую код, код применяет ровно эту скидку. Тестовые (бесплатные) остаются.

- Миграция `007_promo_discount.sql`: `ALTER TABLE promo_codes ADD COLUMN IF NOT EXISTS discount_percent int NOT NULL DEFAULT 100 CHECK (discount_percent BETWEEN 1 AND 100);` (+ `db/schema.sql`). 100 = полностью бесплатный (текущее поведение).
- `scripts/gen-promo.mjs`: третий позиционный аргумент — скидка. `node scripts/gen-promo.mjs 5 SALE 30` → 5 кодов SALE-XXXXXX по 30%. Без аргумента = 100 (обратная совместимость). В stdout печатать код + скидку.
- `lib/promo.ts`: `redeemPromo` возвращает `{ redeemed: boolean; discountPercent: number }` (атомарность UPDATE...RETURNING сохранить).
- `app/api/checkout/route.ts`: промо применён →
  - `discount_percent = 100`: bypass оплаты, сразу processOrder (текущее поведение);
  - `< 100`: сумма = `Math.max(1, Math.round(price * (100 - d) / 100))` руб, платёж ЮKassa на уменьшенную сумму, в description пометка «промокод −N%». Ответ checkout вернуть фронту `discountPercent` и итоговую сумму (UI-хвост покажем после T4e).
- Известное ограничение v1 (зафиксировать в коде комментарием): код сгорает при создании платежа; если юзер не оплатил — код потерян, владелец перевыпускает через CLI.
- Тесты (`order-wishes-storyboard.test.ts` checkout-зона или новый файл): redeem со скидкой уменьшает сумму createPayment; 100% не создаёт платёж; сгоревший код отклоняется.
- Stop: build+typecheck+test зелёные, без коммита.
