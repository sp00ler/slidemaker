## Задачи → агенты → очередь

Роли: **Fable (Claude) = архитектор/ревью/коммит**. Исполнители работают до `npm run build` + `npm run typecheck` + `npm test` зелёные, БЕЗ коммита. Ревью и коммит — архитектор. Деплой — владелец вручную (VPS порт 3001, pm2 `slidemaker`, npm).

### Волна 1 — параллельно (файлы не пересекаются)

**T1. Opus 4.8 — рендер колоды (`lib/pptx.ts`)** — замечания 1, 2, 3
- Fit-contain для diagram/image: читать размеры PNG (сигнатура IHDR), вписывать в регион с сохранением аспекта, центрировать; подпись — ПОД регионом, никогда не поверх.
- Для diagram просить landscape: если Mermaid-граф вертикальный и узлов >5 — направление `LR` (проброс требования в prompt — координация с T2).
- Вариативность content-лейаутов: минимум 3 детерминированных варианта (полоса сверху / вертикальная полоса слева / акцент-блок под заголовком), ротация по индексу слайда, чтобы соседние отличались.
- Section-слайд: убрать 100% заливку accent — светлый фон + крупный accent-элемент (полоса/номер), заголовок без разреженного трекинга.
- Заодно: `FFFFFFCC` (8-hex, строка ~124) → `FFFFFF` + transparency (известный долг).
- Регресс-тест: расширить `lib/__tests__/pptx.test.ts` (аспект не искажается, лейауты чередуются).

**T2. Sonnet 5 — промпты и визуалы (`lib/anthropic.ts`, `lib/visuals.ts`)** — замечания 4, частично 2
- image_prompt: жёсткие константы стиля — светлый фон, flat/minimal editorial иллюстрация, палитра слайда (hex прокинуть), без фотореализма и тёмных сцен.
- Сместить выбор типа визуала: photo/chart/diagram предпочтительнее image; image — только когда остальное не подходит.
- Mermaid: требование «direction LR при >5 узлов», лимит узлов, короткие подписи узлов (<4 слов).
- Палитра: запрет насыщенного accent как полноэкранного фона; разнообразие палитр между заказами (не один синий).
- Текст: плотнее фактура (цифры, конкретика), меньше воды — вторая жалоба владельца сюда же.

**T3. Codex — таблицы из docx (`lib/docx.ts`)** — замечание 6
- Парсить `w:tbl`/`w:tr`/`w:tc` до общего стрипа тегов: таблица → markdown-таблица в text (строки `| a | b |`).
- Лимиты: максимум N таблиц, максимум строк/ячеек, вписаться в существующий `maxTextChars`.
- Тесты в `lib/__tests__/docx.test.ts`: docx с таблицей → markdown в тексте, порядок с абзацами сохранён.

### Волна 2 (v2, утверждена владельцем 02.07) — «Требования к оформлению» + ВКР-каркас

Замечания 7, 8, 9 + идея владельца: университеты диктуют требования к оформлению; сервис должен принимать их, а не заставлять редактировать вручную. Референсы: `docs/pravilaPrezentacii.pdf` (правила СФУ — база default-пресета), `docs/ex1.png`, `docs/ex2.png` (эталон академического стиля: белый фон, тонкие рамки-боксы, нумерация с вертикальными штрихами, ALL-CAPS заголовки, двухколоночная сетка).

**Модель данных — `orders.prefs` JSONB (nullable), миграция `006_order_prefs.sql`:**

```json
{
  "preset": "academic" | "auto" | "custom",
  "workType": "vkr" | "coursework" | "report" | "generic",
  "title": { "mode": "auto" | "self" | "upload", "fileId": "<uuid?>" },
  "fonts": {
    "heading": { "face": "Arial", "size": 32, "bold": true, "italic": false },
    "body": { "face": "Arial", "size": 24 }
  },
  "palette": { "bg": "FFFFFF", "text": "1A1A1A", "accent": "1F3A5F" }
}
```

- `preset: "auto"` = текущее поведение (ИИ подбирает всё) — prefs может быть null.
- `preset: "academic"` = default для новых заказов. Фиксированный DesignSpec: bg `FFFFFF`, ink `#1A1A1A`, один сдержанный accent (тёмно-синий `1F3A5F`) только на номера/штрихи/подчёркивания; стандартные шрифты (Arial default; select: Times New Roman, Arial, Tahoma, Verdana, Calibri); минимум декора; ALL-CAPS только в заголовках слайдов.
- `preset: "custom"` = юзер крутит шрифты/размеры/палитру сам (свёрнутая секция).
- Шрифты — только whitelist стандартных (есть на любой машине, pptx не тащит embed).

**T4a. Opus 4.8 — academic-рендер + DesignSpec в `lib/pptx.ts`**
- Новый themeFromPrefs: DesignSpec переопределяет Theme (fontFace/размеры/палитра) поверх пресетов.
- Academic-лейауты по ex1/ex2: тонкие рамки-боксы (1pt line), нумерованные блоки с вертикальным штрихом-акцентом, двухколоночная боксовая сетка для перечислений, заголовок слайда ALL-CAPS по центру с accent-подчёркиванием. Ротация лейаутов волны 1 сохраняется, но в academic — свои 3 варианта.
- Титул: `title.mode="self"` → колода без титульного слайда; `"upload"` → загруженный PNG/JPG первым слайдом full-bleed (reuse `order_files`, kind `title`). Импорт чужого .pptx НЕ делаем (pptxgenjs не умеет merge).
- Тесты: prefs переопределяет fontFace, academic без цветного фона, self-режим не рендерит титул.

**T4b. Sonnet 5 — ВКР-каркас + academic-правила текста в `lib/anthropic.ts`**
- `workType="vkr"` → фиксированная последовательность (PDF п.14): титул (если не self/upload) → «Цель работы и задачи» (цель конкретно+измеримо, задачи нумерованным списком) → описание проблемы/объекта → этапы решения → конкретный результат («проведены… созданы… разработаны…») → заключение. `coursework` — то же без строгости, `report/generic` — текущее поведение.
- Academic-пресет: буллеты ≤3 на слайд, ≤8 слов (body 24–28pt обязан влезать), без англицизмов кроме общепринятых (PDF п.12–13), сдержанные палитры игнорируются — палитра приходит из prefs.
- Прокинуть prefs в buildDeckPrompt/buildTopUpPrompt параметрами.
- Тесты: vkr-каркас даёт нужные слайды в нужном порядке (по мокнутому ответу).

**T4c. Codex — форма «Оформление» + сквозной проброс**
- `app/page.tsx`, раздел «Оформление» в форме заказа: радио пресетов (Академический default / ИИ решает / Свои настройки) + select «Тип работы» + блок «Первый слайд» (радио: сгенерировать / оформлю сам / загрузить свой PNG-титул → reuse upload-механизм). Custom-настройки в `<details>`: шрифты (select), размеры, палитра (hex-инпуты + 5–6 пресетов стандартных Office-тем).
- Zod-схема prefs в `lib/checkout-validation.ts` (whitelist шрифтов, hex-валидация, лимиты размеров 16–40pt).
- Миграция `006_order_prefs.sql`; `lib/orders.ts` createOrder + чтение; `lib/generate.ts` проброс prefs в anthropic и pptx; `/api/regenerate` наследует prefs родителя.
- Тесты: zod отбрасывает мусор, prefs сохраняется и доходит до generateDeck/buildPptx (стабы).

**T4d. Sonnet 5 — live-превью (после мержа T4c, тот же page.tsx)**
- CSS-миниатюра слайда 16:9 рядом с настройками: заголовок + буллеты + рамки, мгновенно реагирует на пресет/шрифт/размер/палитру (чистый React state, без бэка).
- При academic-пресете — подпись «Стиль по умолчанию — академический» + мини-мокап в стилистике ex1/ex2.
- Честное ограничение в UI: «превью схематично, финальный рендер в PowerPoint может отличаться в деталях».
- Это же закрывает замечание 9 (превью стилей) — карточки стилей волны 3 переиспользуют компонент.

**Очередь волны 2:** T4a + T4b параллельно (pptx vs anthropic, не пересекаются) → ревью+коммит → T4c (page.tsx, checkout, orders, generate, миграция) → ревью+коммит → T4d (page.tsx превью) → Haiku QA всей волны → деплой с миграцией 006.

**Примечание:** «стилистика» (Деловой/Креативный/Минимализм) остаётся и переименовывается по смыслу в «стиль повествования» — влияет на текст, НЕ на оформление. Оформление = prefs.
