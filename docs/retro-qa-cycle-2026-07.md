## Волна 2.3 — второй прогон тестировщика (04.07)

Четыре жалобы по живому .pptx, все — рендер/промпт:

1. **Каждый тезис своего кегля** (главный факап). Причина: `academicNumbered`/`academicTwoColumns` считали `fitBodyFontSize` НА КАЖДЫЙ буллет — короткий крупно, длинный мелко. Фикс: единый кегль = `Math.min` по всем буллетам, один на все блоки.
2. **Заголовки лезут на accent-полосу** (сл. 4,6,7,9–13). Причина: `fit:"shrink"` мёртв на просмотре (урок 1) — длинный заголовок в 2 строки вылезал за бокс на подчёркивание. Фикс: `fitHeadingFontSize` — кегль заголовка считаем сами (charW ≈ 0.62*pt), `fit:"shrink"` убран.
3. **Схемы мелкие** (сл. 5,8,11,14). Причина: порог «широкий» 2.0 → большинство схем в узком боковом регионе; нижняя полоса низкая. Фикс: `WIDE_ASPECT` 2.0→1.5, полоса выше и крупнее (`y4.05 h2.95` вместо `y4.65 h2.25`), текст-регионы подняты над ней.
4. **AI-иллюстрация на английском** (сл. 3, работа русская). Причина: image-модель не умеет кириллицу, пишет английский/мусор. Фикс: academic-пресет запрещает `visual type "image"` в промпте + страховочный дроп `kind "image"` в рендере (chart/photo/diagram/none остаются). Промпт academic: весь текст строго на языке темы, заголовок ≤6 слов.

Урок подтверждён снова: юнит-аудит зелёный, все 4 бага ловит только живой .pptx владельца. Каждый баг закрыт регресс-тестом (единый кегль, широкий upload-визуал в academic). 58/58.

## Что сработало

1. **Конвейер брифов**: самодостаточный бриф в `docs/qa-yulenka-plan.md` → параллельные исполнители по непересекающимся файлам → ревью Fable с собственным прогоном ворот (typecheck/test/build) → атомарные коммиты. Ни одного конфликта между агентами за цикл.
2. **Ревью не на слово**. Каждый отчёт перепроверялся по diff. Улов ревью, который прошёл мимо исполнителей и Haiku-аудита: битый SQL в saveTitleUpload (`$1` заменён огрызком комментария — упало бы на первом же upload), hardcoded 28/18pt мимо prefs, `undefined` в промпт при частичной палитре, auto-пресет схлопывал workType/титул (жил с T4c).
3. **Живые прогоны владельца — главный QA.** Код-аудит Haiku дал 8.5/10 и не заметил ни одного из четырёх рендер-багов, которые владелец увидел глазами за минуту. Скриншот бьёт чек-лист.
4. **Фиксы с регресс-тестами.** Каждый пойманный баг закрыт тестом (кегль-переполнение, консистентный декор, bottom-band, реген-цепочка, параметризованный SQL). Второй раз та же дыра не откроется молча.

## Уроки (чтобы не повторять)

1. **pptxgenjs `fit:"shrink"` не работает на просмотре** — пишет normAutofit, который PowerPoint пересчитывает только при редактировании textbox. Любой автофит библиотеки проверять по выходному файлу; геометрию считать самим (`fitBodyFontSize`).
2. **«Лечишь одно — заболевает другое»**: в рендере два параллельных пути (обычный + academic). Фикс bottom-band вшили в один — второй сломался на первом же прогоне. Правило: любой фикс геометрии применять и тестировать на ОБОИХ путях.
3. **Дыры экономики находит только e2e.** Бесконечный реген (child order с собственным regen_used=false, orderId в ответе API) не ловился ни юнитами, ни аудитом — только живым кликом владельца. Инварианты денег (кто и сколько раз получает бесплатное) фиксировать тестами при проектировании, не после.
4. **Фича без UX-обвязки = «хули это даёт»**: голые hex-инпуты и свёрнутый блок внизу формы прочитались как неработающая фича. Label + hint + мгновенный превью-отклик — часть фичи, не полировка после.
5. **Новый функционал сразу проектировать на все точки входа.** «Оформление» добавили на главной, забыли в ЛК — владелец нашёл через полчаса. Чек: заказ, реген, (будущие) админка/API.
6. **Победивший дизайн-принцип**: никакого декора без функции (полосы вон, остался только accent-underline заголовка); вариативность колоды — из визуалов, не из украшательств.
